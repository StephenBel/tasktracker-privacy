# MacBridge

Экран Мака в телефоне: посмотреть, приблизить нужную область, тапнуть вместо клика, набрать текст.
Состоит из двух частей:

- **`host/`** — программа для Мака (Electron), живёт в строке меню. Захватывает экран, отправляет его
  телефону и выполняет пришедшие клики и нажатия клавиш.
- **`web/`** — страница для телефона. Открывается в Safari, её можно добавить на экран «Домой»;
  позже её же можно обернуть в Telegram Mini App или в нативное приложение.

Видео и команды идут напрямую между телефоном и Маком по WebRTC. Чтобы устройства нашли друг друга
в интернете, нужен сервер-посредник (Supabase Realtime); через него проходят только зашифрованные
служебные сообщения.

## Жесты на телефоне

| Жест | Что происходит на Маке |
| --- | --- |
| Тап | Клик |
| Двойной тап | Двойной клик |
| Долгое нажатие или тап двумя пальцами | Правый клик |
| Долгое нажатие, затем движение | Перетаскивание с зажатой кнопкой (выделить текст, подвинуть окно) |
| Движение двумя пальцами | Прокрутка |
| Щипок | Зум картинки (на Мак ничего не отправляется) |
| Движение одним пальцем | Сдвиг приближенной картинки |

Кнопки внизу: клавиатура (с рядом esc / tab / ⌘ ⌥ ⌃ ⇧ / стрелки / «Вставить»), лупа
(весь экран ↔ последнее приближение), переключение монитора, меню подключения.
Модификатор действует на одну следующую клавишу: `⌘`, затем `c` — это ⌘C.

## Запуск на Маке

Нужны Node.js 20+ и Xcode Command Line Tools (`xcode-select --install`) — ими собирается маленький
помощник `host/helper.swift`, который вводит клики и клавиши.

```sh
cd macbridge
npm install        # заодно соберёт помощник ввода
# заполнить config.json (см. ниже)
npm start
```

При первом запуске macOS попросит два разрешения (Системные настройки → Конфиденциальность и
безопасность): **Запись экрана** и **Универсальный доступ**. При запуске через `npm start` в списке
будет «Electron» или ваш терминал — разрешение нужно дать тому, кого назовёт macOS. После выдачи
«Записи экрана» приложение нужно перезапустить.

Дальше: значок в строке меню → «Подключить телефон…» → навести камеру телефона на QR-код.

## Что уже настроено

- Страница для телефона опубликована: <https://macbridge-puce.vercel.app/> (проект `macbridge` в Vercel).
  Она не привязана к репозиторию и сама не обновляется: после правок в `web/` или `shared/` её нужно
  опубликовать заново.
- Посредник — Realtime проекта Supabase `crmframe`. Используется только канал широковещательных
  сообщений; в базу данных ничего не пишется.

Оба значения уже вписаны в `config.json`, править его для первого запуска не нужно.

## config.json

```json
{
  "clientUrl": "https://адрес-страницы-для-телефона/",
  "signal": { "type": "supabase", "url": "https://<проект>.supabase.co", "key": "<publishable key>" },
  "iceServers": [{ "urls": ["stun:stun.l.google.com:19302"] }],
  "video": { "maxWidth": 2560, "maxFps": 30, "maxBitrate": 8000000 }
}
```

- `clientUrl` — где опубликована папка `web/dist` (обязательно https).
- `signal` — посредник. Ключ Supabase здесь публичный («publishable»), секретов в файле нет.
  Вместо Supabase можно поднять свой `dev/relay.mjs`: `{"type":"relay","url":"wss://..."}`.
- `iceServers` — если телефон и Мак не могут соединиться напрямую (строгий NAT у мобильного
  оператора), сюда добавляется TURN-сервер.

Конфигурация вшивается и в программу для Мака, и в страницу при `npm run build`,
поэтому после правки нужно пересобрать и заново опубликовать `web/dist`.

## Как устроена безопасность

- **Сопряжение.** QR-код содержит публичный ключ Мака и одноразовый секрет (5 минут, одно
  использование). Телефон создаёт свою пару ключей; общий долговременный ключ получается через
  ECDH и никогда не передаётся по сети. Секрет лежит во фрагменте ссылки (`#…`), который браузер не
  отправляет серверу, и сразу стирается из адресной строки.
- **Каждое подключение.** Запрос телефона и ответ Мака (включая отпечатки ключей WebRTC) зашифрованы
  и подписаны этим ключом (AES-GCM). Посредник не может ни прочитать их, ни подменить, поэтому не
  может вклиниться в соединение. Повтор старого запроса отбрасывается.
- **Данные.** Видео и ввод идут по WebRTC (DTLS-SRTP), мимо посредника.
- **На Маке.** Ключи хранятся зашифрованными через Связку ключей. Пока кто-то подключён, в строке
  меню горит «●» и приходит уведомление. Доступ устройства отзывается в меню «Доверенные
  устройства»; «Отключить сейчас» разрывает текущий сеанс.
- **На телефоне.** Ключ хранится в браузере в неизвлекаемом виде. Кто получил разблокированный
  телефон — получил и доступ к Маку, пока его не отозвать.
- **Чему приходится доверять.** Хостингу страницы `web/dist`: тот, кто может подменить её код,
  может управлять Маком от вашего имени. Нативное приложение снимет эту зависимость.

## Ограничения

- Мак должен быть включён и не спать (пункт меню «Не давать Маку засыпать» включён по умолчанию;
  закрытая крышка без внешнего монитора всё равно усыпляет MacBook).
- Экран блокировки macOS обычным программам недоступен: разблокировать Мак с телефона нельзя.
- Автозапуск при входе в систему появится после упаковки в `.app` (следующий шаг).
- Звук не передаётся.

## Проверка

```sh
npm test                                   # страница-«Мак» и страница-«телефон» в headless Chromium
SIGNAL=config CLIENT=config npm test       # то же через настоящий Supabase и опубликованную страницу
xvfb-run -a npm run test:electron          # настоящий Electron под виртуальным экраном (Linux)
```

Тестам нужен глобально установленный Playwright. Они покрывают сопряжение, шифрование сигналинга,
передачу видео, все жесты, клавиатуру, переподключение и отзыв доступа. **Не покрыто тестами**
(нужен настоящий Мак и iPhone): сборка и работа `helper.swift`, системные разрешения macOS,
поведение клавиатуры iOS Safari, соединение через мобильную сеть (может понадобиться TURN).
